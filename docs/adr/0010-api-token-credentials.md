# ADR 0010: Internal API-token credentials

Status: Accepted. Approval: ARCHITECT role, 2026-10-22.
Owner: CORE-BACKEND. Required reviewer: QA-SECURITY. Scope: WP-1.1 credential slice.

Introduce an internal standard-library credential primitive without persistence,
HTTP handlers or protobuf changes. This approval does not expose authentication
or complete API-token support. Subsequent contracts require a separate ADR.

Use `forge_v1.<selector>.<secret>` with a 16-byte public selector and 32-byte
secret generated by crypto/rand. Encode both as unpadded base64url. The selector
is a lookup hint, never proof of identity or organization membership. Generation
fails without returning partial credentials if randomness acquisition fails.

Parse only the exact prefix, component count, fixed lengths and canonical
encoding. Reject whitespace, padding, alternate encodings and malformed input
without echoing credentials. Hash the complete canonical token with SHA-256;
this binds version and selector as well as its 256-bit random secret. The high
entropy secret permits a fast one-way verifier; this is not password hashing.
Compare fixed-size digests using crypto/subtle constant-time comparison.

Return plaintext only for issuance; persist only the digest in a later slice.
Do not log tokens, verifier bytes or authentication payloads. Tests use the
shared secret-leak helper for errors/log formatting and cover malformed inputs,
wrong secrets/selectors, unsupported versions, canonicalization and entropy
failure. Credential-bearing values should redact normal diagnostic formatting.

Before authentication is exposed, bind selector/digest to an organization and
current user membership under forced RLS and explicit organization predicates.
Require expiration, revocation and scoped permissions intersected with current
membership permissions; a token must not preserve privileges after demotion.
Use WithOrg from established authorization, never trust selector or request org
alone. Unknown selectors fail closed with generic authentication errors.
Issuance/revocation and their audit events must commit atomically, and plaintext
must be delivered once over authenticated transport. Rate limiting and tenant
resolution need explicit designs before public token authentication is wired.

Acceptance for this bounded slice: unit and leak tests, at least 70% business
logic coverage, QA-SECURITY review and existing CI green. No new dependency or
schema is needed. Keep the complete proposed PR below 500 changed lines.
