# Operator organization bootstrap

`go run ./cmd/bootstrap` provisions a new organization and its known initial
admin, recording `organization.bootstrap` in the same transaction. Run after
migrations, as an operator process; never configure this in server startup.

Supply these environment variables through your operator secret/config tooling:

- `FORGE_BOOTSTRAP_OWNER_URL`: separate schema-owner PostgreSQL URL; there is no
  fallback to `DATABASE_URL`. The authenticated role must own orgs/users/audit_events
  and have NOSUPERUSER/NOBYPASSRLS; all three tables must have forced RLS.
  PostgreSQL image bootstrap superusers are rejected; provision a distinct
  non-superuser schema owner.
- `FORGE_BOOTSTRAP_ORG_ID`, `FORGE_BOOTSTRAP_ADMIN_ID`: canonical lowercase,
  nonzero UUIDs generated by the operator.
- `FORGE_BOOTSTRAP_ORG_NAME`, `FORGE_BOOTSTRAP_ADMIN_NAME`: 1–200 UTF-8 bytes.
- `FORGE_BOOTSTRAP_OIDC_ISSUER`: exact configured HTTPS issuer, up to 2048 bytes,
  without credentials, query or fragment.
- `FORGE_BOOTSTRAP_OIDC_SUBJECT`: independently confirmed exact subject, 1–255 bytes.

Text must have no control characters or surrounding whitespace. No arguments are
accepted. Success prints only the org UUID. Any conflict/failure exits nonzero
with a generic error; do not retry using an existing organization to add members.
Each invocation provisions one new organization; other organizations may exist.
The command neither verifies identity tokens nor contacts the provider. Remove
owner configuration from the process environment after use; runtime processes use
their separately provisioned non-owner role. [ADR0015](../adr/0015-operator-bootstrap.md) and implementation passed
ARCHITECT/QA-SECURITY review; CI acceptance still gates the slice.

For local Compose only, the owner URL is
`postgres://forge_owner:forge-owner-dev-only@localhost:5432/forge?sslmode=disable`.
These credentials are development fixtures.

Existing PostgreSQL volumes do not rerun `init.sql`, and the initdb bootstrap
superuser cannot be demoted. Use an operator-reviewed backup/restore into a fresh
cluster with a distinct non-superuser schema owner. Keep the original volume
intact until the restore, ownership and application checks pass; there is no
automatic upgrade or data deletion. Keep maintenance credentials out of
server/worker and bootstrap environments; bootstrap uses only the owner URL.
Production requires independently provisioned roles/credentials.
